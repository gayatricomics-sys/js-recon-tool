JS Recon - Burp Suite extension (offline package)  v1.7.0
=========================================================

Everything needed is in this folder. No internet access is required.

  js_recon_burp.py              the Burp extension (Jython / Python 2.7)
  jython-standalone-2.7.4.jar   Jython runtime Burp needs to run Python extensions
                                (official build, SHA-1 df61c8c28ce458bc84d92a12aaaf20b15dbc55db)
  run_selftest.sh               offline self-test (optional)
  selftest/                     files used by the self-test

The extension uses only the Python 2.7 standard library bundled inside the
Jython jar plus Java/Swing classes, so there is nothing else to install.

INSTALL (offline)
-----------------
1. Copy this whole folder to the offline machine.
2. Burp Suite -> Settings -> Extensions -> Python environment
   (older Burp: Extender -> Options -> Python Environment)
   -> "Location of Jython standalone JAR file" -> select
   jython-standalone-2.7.4.jar from this folder.
3. Extensions -> Installed -> Add -> Extension type: Python ->
   select js_recon_burp.py -> Next.
4. The Output tab should show "[JS Recon] JS Recon 1.7.0 loaded." and the
   Errors tab should be empty. A new "JS Recon" tab appears.

USE
---
- Add your target to Burp's scope (Target -> Site map -> right-click host ->
  Add to scope). Burp's Target scope IS the authorization: no host box or
  checkbox to fill in. Out-of-scope hosts stay passive (no PoCs).
- Browse the target through Burp Proxy. JavaScript responses (by response
  Content-Type, Burp's MIME detection, or .js/.mjs/.cjs path) from in-scope
  hosts are analyzed automatically. Untick "In-scope only" to capture all JS.
- Right-click any request in Proxy / HTTP history / Repeater -> Send to JS Recon.
- Find: type text and press Enter (or Find). All tables are filtered to
  matching rows, the status bar shows the counts, and the first match is
  highlighted in the JS Files source view. Empty the box + Find to show all.
- Host filter: type a host and press Enter to re-filter existing findings.
- DOM XSS tab: select a row -> "Copy PoC" copies a marker payload for an
  in-scope host. Nothing is sent automatically; you test it manually.
- Export CSV / Export HTML write UTF-8 files (HTML output is escaped).
- Export PoCs: writes an HTML + Markdown report of every in-scope DOM XSS
  finding with its exact copy-paste payload, the vulnerable line, the likely
  client-controllable source, and concrete steps to reproduce -- ready to
  paste into a finding. Out-of-scope hosts are omitted.
- Active DOM XSS verification (second toolbar row, in-scope hosts only):
  * Set "Target page URL" to the page that loads the vulnerable script.
  * Select a DOM XSS row, then "Fire in browser" builds the test URL
    (for URL-based sources: hash/query) and, after a confirmation where
    you can edit the exact URL, opens it in your default browser.
  * When the alert pops, "Capture screenshot" grabs the screen (or
    "Attach screenshot file" uses an image you took) and attaches it to
    the finding. Export PoCs then embeds the popup screenshot and a
    "How to execute" section in the HTML/Markdown report.
  * Non-URL sources are handled too: postMessage and window.name open an
    auto-generated trigger harness page; cookie/localStorage/sessionStorage
    give a console snippet (copied) to paste on the target; referrer and
    unknown sources show manual steps.
  * "Fire + capture PoC" fires, waits "Capture delay s" seconds, auto-
    captures the screen (the alert), attaches it, and saves this finding as
    a one-off PoC (HTML + Markdown) with the screenshot.
  * The PoC also shows the "Effective code after injecting the payload".
  * Screenshots capture the BROWSER ALERT, not Burp: the Burp window is
    minimized for ~1s during the shot, then restored. For a tight popup-
    only image, take an OS screenshot of the alert and use "Attach
    screenshot file" instead.
  * "Use Burp browser" (on by default): fires in Burp's bundled Chromium,
    launched with Burp's proxy and --ignore-certificate-errors, so traffic
    goes through Burp. If the browser binary isn't found it falls back to your
    default browser.
  * Console snippets and manual steps are shown in a selectable/copyable text
    box, and the trigger (console snippet / harness / test URL) is also included
    in the PoC report so it can be copied there.
  NOTE: firing opens the LIVE target; only in-scope hosts are allowed, and
  every fire is confirmed first.

SELF-TEST (optional, offline)
-----------------------------
  sh run_selftest.sh
Every line should start with [OK]; there should be no [FAIL].

ANALYSIS (v1.7.0)
-----------------
- JavaScript is beautified first (minified bundles become readable), then
  lexed into tokens. Endpoint / secret / DOM XSS / sensitive-function
  detection runs over tokens, not regex over raw text, so findings are not
  produced from inside string literals or comments.
- Endpoints include URLs built by concatenation and template literals
  (base + "/api/" + id  ->  {param} placeholders).
- The JS Files detail pane lists sensitive-looking functions and shows the
  beautified source; line numbers in findings refer to the beautified text.

LIMITS (static heuristics - always verify manually)
---------------------------------------------------
- Regex-based, not a JS parser: taint tracking is best-effort, so expect some
  false positives and negatives. Findings are leads, not confirmed bugs.
- Inline <script> blocks inside HTML pages are not analyzed (only JS responses).
- Secrets are shown redacted; the full value is in the captured source
  (JS Files tab detail pane) at the listed line.
- Files larger than 8 MB are skipped (logged in the Log tab).
